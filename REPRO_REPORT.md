# Reproducibility report: ecis2027_repro

Package for the ECIS 2027 completed-research paper "No Results Found": Evidential Access and the Automated Assurance
of Agentic Health Information Systems (manuscript v3). Built and tested on 28 Sep 2026 on native Windows 11
(16 CPUs, no GPU, no network egress), Python 3.11.16, numpy 2.4.6, pandas 2.3.3, matplotlib 3.11.2.

## 1. Result

**Level A reproduces every published derived table, both figures and all 186 checked manuscript numbers.** Tested from a
fresh unzip of `ecis2027_repro.zip` into a new temporary directory with `python reproduce.py --level A`:
`ALL CHECKS PASSED (205 checks)`, 17 of 17 published CSVs **identical** (including all bootstrap intervals),
2 of 2 figures regenerated at the published pixel size, 186 of 186 numbers within tolerance. Runtime 189 s.

**Level B** (re-running the experiments, with the paper's or other LLMs) is complete as code and configuration but
was **not run against live models or a live FHIR server** (no network in this environment). What was executed
instead: syntax checks of every script, dry runs of three configs, an offline chain test of steps 3-10 on the archived
data (205 of 205 checks pass), a mock-endpoint test of the agent, judge and probe code paths (9 of 9 pass), a prompt
fidelity test (15 of 15 prompt files identical to the code) and the paid-step guards.

Additional checks produced along the way: the 121 GPT-agent substantive errors re-coded from their raw trajectories
with the published provenance rules agree with the archived coding in 121 of 121 cases (provenance and basis); the
stratified 418-attempt record-access sample re-drawn with seed 2027 is identical to the archived sample; the offline
regrade of the 480 pilot attempts agrees with the server-graded classes in 480 of 480 cases.

How exact reproduction was achieved (reconstruction notes):
* Every analysis script was rebuilt from the lineage code of the published CSVs and from the original analysis cells
  (execution log of the analysis session), rewritten to read `data/` paths, with no artifact markers or host calls.
* The task-clustered bootstraps depend on the order of tasks; the loaders keep the original row order (pilot attempts in
  `results.jsonl` order, DeepSeek attempts in tracer order).
* The record-access J intervals were drawn in the original session from the generator left over from the cue
  bootstrap (default_rng(2026) after 6 x 4,000 draws). `common.record_access_rng()` replays those draws; without this the
  intervals differ by up to 0.033.
* Table 5 "official pass" includes passes on do-nothing tasks (all grader passes); with this definition 0.66-0.83 is
  reproduced (0.654 otherwise).
* Two numbers are reproduced only because the paper rounded a 3-decimal CSV value a second time (0.105 printed as 0.10,
  0.895 as 0.90); `paper_numbers.csv` notes this and uses a tolerance of 0.006 for them.
* The GPT judges ran with judge_runs v1, the DeepSeek judges with the final v3; the rendered neutral prompt is identical
  (v3 only adds an empty `{checks}` slot).

## 4. Gaps (cannot be reproduced from the archive)
1. **Raw trajectories not archived** of the DeepSeek V3.2 full run (`full_deepseekv32`, 1,200 attempts), the cue run
   (`cue_deepseekv32`, 166 attempts), the 2026-09-26 smoke runs of other OpenRouter models, and the 300-task control
   runs (`full_control_replay`, `full_control_null`). Level A starts from the archived per-attempt tables for these
   (`full_deepseekv32_mechanisms.csv`, `cue_deepseekv32_mechanisms.csv`, DeepSeek rows of `provenance_coding.csv`,
   `first_query_codes.csv`); `data/raw/full_deepseekv32/README.md` explains how to drop the author's folder in and which
   scripts then run from raw (provenance, first-query codes, probe items; tracer and regrade with the server). Numbers
   resting on these tables are reproduced from the tables, not from raw outputs.
2. **Steps that need the live FHIR server** were not re-executed: format-only regrade (outcome classes; archived
   server-graded classes used), mechanism tracer (archived tracer output; hand-traced pilot codes), probe controls and
   the record-access judge's EHR queries.
3. **"70 of 300 tasks" (do-nothing agent, 5.3)** rests on `full_control_null`, which is not archived; the 30-task
   control gives 7/30 = 0.23, the same rounded share used in Table 5 and Figure 2.
4. **Manuscript numbers whose computation is not archived** (not in paper_numbers.csv; for the author to confirm):
   * 5.5 and Table 7: "16 rationales called the potassium search 'the correct LOINC code'". The archived verdicts give
     **14** such rationales in the two API-specification conditions (18 across all judge conditions); the exact count
     rule behind 16 could not be recovered.
   * 5.6: "94-96% of rejected false absences, and 56-69% of rejected incomplete retrievals" named the actual error. The
     classification rule is not archived; plausible keyword rules give 0.88-0.96 and 0.80-0.97, so these shares are
     regex-dependent and were not verified.
5. **Second-coder reliability** (the [AUTHOR INPUT REQUIRED] / [INSERT FINAL IRR RESULT] placeholders of 4.4, 5.1, 6.3)
   has no data in the archive.
6. **Level B not run live**: no call to OpenAI, OpenRouter, NVIDIA NIM, Groq or a local model server, and no FHIR server
   start (the 4.5 GB server image is downloaded from Docker Hub by `fetch_server.py`; the harness zips contain only
   the h2fix jars). The mock test replaces the model endpoint and the FHIR server with local replays.
7. The `.sh` script was not syntax-checked (no bash on this host); the `.ps1` script parses without errors.

## 6. Secret and path scan
All text files of the package (1,533 at scan time; the README and this report were re-scanned after editing) (code, configs, CSV, JSON/JSONL trajectories and verdicts, logs, Markdown) were
scanned for key-like strings (`sk-...`, `sk-or-...`, `nvapi-...`, `gsk_...`, `Bearer <token>`, `api_key="..."`) and for
personal paths (Windows user-profile paths, `/Users/...`, `/home/...`, the user name, the app data folder): **0 hits**. The loose
patterns occur only as code (`api_key=_llm.api_key(env)` reading an environment variable; `Bearer {token}` for the
anonymous Docker Hub token in `fetch_server.py`). Absolute paths in the lineage code (artifact store, conda envs) were
replaced by package-relative paths; the pipeline prints package-relative commands. The 3,198 binary files are the
extracted H2/Spring class files and the figure PNG/PDFs. Keys are read only from the environment variables named in
the configs.

## 7. Costs (from the paper's runs)
About 9-10k tokens per GPT agent attempt (8,600 prompt of which about 7,200 cached, 90 completion); about USD 0.0016
per DeepSeek attempt; about USD 0.0005 per DeepSeek trajectory-only verdict and USD 0.0018-0.0020 with record access;
about USD 0.0002 per probe call. A full replication of the paper setup costs roughly USD 15-20 at list prices before
cache discounts and takes 6-10 hours (details in README, "Costs and runtimes").
